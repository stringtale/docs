A reference guide for all CLI options. Note that all subcommands can be run with the `--help` option to display more information about the command.

## Installation

You can install the CLI globally using your JavaScript package manager. Or use your package manager to run it directly.

To install globally you can use:

<Tabs>
  <TabItem label="npm">
    ```bash
      npm install -g @stringtale/cli
    ```
  </TabItem>
  <TabItem label="Yarn v1 / v2">
    ```bash
      yarn global add @stringtale/cli
    ```
    **Note:** Installing npm packages globally is no longer supported as of Yarn v3. See below how you can run it directly instead.
  </TabItem>
  <TabItem label="pnpm">
    ```bash
      pnpm install -g @stringtale/cli
    ```
  </TabItem>
</Tabs>

To run Stringtale directly:

<Tabs>
  <TabItem label="npm / npx">
    ```bash
      npx @stringtale/cli
    ```
  </TabItem>
  <TabItem label="Yarn v3+">
    ```bash
      yarn dlx @stringtale/cli
    ```
  </TabItem>
  <TabItem label="pnpm">
    ```bash
      pnpm exec @stringtale/cli
    ```
  </TabItem>
</Tabs>

## Basic usage command

You can use the Stringtale CLI as follows.

```bash
stringtale [command] [options]
```

<Aside type="tip">
  If you decide to use the CLI directly without installing, replace `stringtale [command]` with
  `npx @stringtale/cli [command]`, `yarn dlx @stringtale/cli [command]`, or `pnpm exec @stringtale/cli [command]`.
</Aside>

## Commands

### `login`

Authenticates the Stringtale CLI with the [dashboard](https://stringtale.com/app/projects). The CLI stores your unencrypted session token in
`~/.config/stringtale/token.json`.

### `init`

Automatically integrates Stringtale into a new or existing project. It will offer to select an existing project in Stringtale or create a new one.
After selecting which framework you use it will take the required steps to integrate Stringtale within your project, for example creating
`app/api/stringtale/route.ts` with `setupNextAppRoute` for the Next.js App router, or `pages/api/stringtale.ts` with `setupRoute` for the Pages router.
For more information see our [Installation](/guides/getting-started/) guide.

### `pull`

Pull in text edits from Stringtale to your local source code. You can use this if your code isn't hosted by GitHub or you don't want to use
the GitHub Action.

### `codemod` (prior to v0.6.0 `wrap`)

Automatically wraps all plain text in your source code in `<Value>` tags so they can be edited once Stringtale is activated.

### `logout`

Signs out Stringtale and deletes your local token from `~/.config/stringtale/token.json`.

## Options

Options can be used to modify the behavior of the command. The list below is not exhaustive, but rather a list of common options that are used with most commands.

### `-e` option

The `-e` option can be used as a boolean in conjunction with any of the other commands. When used the `.env` file from the current working directory will be loaded and used to authenticate.

### `--help` option

The `--help` option can be used as a boolean in conjunction with any of the other commands. Doing so will print additional information for options that can be used with that command.

## Environment variables

### `STRINGTALE_API_KEY`

The `STRINGTALE_API_KEY` is a project-based API key. It can be used to pull in text edits from Stringtale to your local source code. You can use this with the CLI if your code isn't
hosted by GitHub or you don't want to use the GitHub Action. See [Obtaining an API key](/usage/obtaining-api-key/).
